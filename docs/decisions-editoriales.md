# Décisions éditoriales - Projet Histoire d'os

## 1. Fonction du document

Ce document fixe les principales décisions éditoriales, pédagogiques, scientifiques et techniques du projet Histoire d'os.

Il sert de référence pour :

- la rédaction des contenus ;
- la création des activités ;
- la navigation du site ;
- la production des supports imprimables ;
- l'intégration des médias ;
- l'utilisation de l'intelligence artificielle ;
- la publication et la validation des ressources.

Il complète `AGENTS.md`, la compétence locale `histoire-os-publisher`, `docs/workflow-codex.md` et `docs/validation-checklist.md`.

En cas de contradiction :

1. les exigences scientifiques et juridiques priment ;
2. `AGENTS.md` fixe les règles générales de travail ;
3. le présent document fixe les choix éditoriaux ;
4. les cahiers des charges propres à chaque activité précisent les livrables.

## 2. Mission générale du projet

Histoire d'os propose des ressources scientifiques et pédagogiques consacrées aux astragales et aux osselets.

Le projet vise à faire comprendre qu'un même os peut être étudié sous plusieurs dimensions :

- anatomique ;
- zoologique ;
- archéozoologique ;
- historique ;
- linguistique ;
- mythologique ;
- ludique ;
- sociale ;
- rituelle ;
- symbolique ;
- muséale.

Le site ne doit pas seulement transmettre des réponses. Il doit rendre visibles les démarches qui permettent de construire, vérifier et nuancer les connaissances.

Les contenus doivent combattre les récits trop simples ou historiquement inexacts, notamment lorsqu'ils transforment une interprétation discutée en fait établi.

## 3. Publics du site

Le site distingue quatre publics principaux.

### 3.1 Enseignantes et enseignants

Les enseignantes et enseignants recherchent des ressources :

- rapides à comprendre ;
- faciles à imprimer ;
- directement utilisables ;
- adaptées aux élèves de 8 à 12 ans ;
- liées à des objectifs d'apprentissage ;
- accompagnées d'une correction ;
- intégrables dans une séquence ;
- reliées prudemment au Plan d'études romand.

Depuis leur page d'entrée, les enseignantes et enseignants doivent pouvoir accéder en deux clics maximum à :

1. la fiche élève ;
2. le guide enseignant ;
3. le corrigé ou l'évaluation.

Les informations essentielles doivent apparaître immédiatement :

- âge ;
- durée ;
- matériel ;
- objectifs ;
- organisation ;
- activité préalable éventuelle ;
- statut de validation ;
- statut d'impression.

### 3.2 Musées et médiation

Les musées recherchent des activités :

- simples à préparer ;
- faciles à adapter aux collections ;
- imprimables ;
- utilisables avec ou sans objets manipulables ;
- accompagnées de relances ;
- compatibles avec les contraintes de circulation et de conservation ;
- accessibles à différents publics.

Chaque dossier musée doit préciser :

- type de collection nécessaire ;
- matériel minimal ;
- durée ;
- taille des groupes ;
- déroulement ;
- organisation de l'espace ;
- relances ;
- règles de manipulation ;
- variantes ;
- accessibilité ;
- éléments à adapter par l'institution.

### 3.3 Familles et grand public

Le parcours famille doit permettre une découverte autonome et courte.

Il privilégie :

- des textes brefs ;
- des récits ;
- des images ;
- des modèles ;
- des activités simples ;
- un vocabulaire expliqué ;
- des ouvertures vers les dossiers plus détaillés.

Il ne doit pas reproduire les guides professionnels destinés aux adultes.

### 3.4 Approfondissement scientifique

La section d'approfondissement est destinée notamment :

- aux chercheuses et chercheurs ;
- aux étudiantes et étudiants ;
- aux enseignantes et enseignants souhaitant approfondir ;
- aux professionnelles et professionnels des musées ;
- aux personnes intéressées par les sources et la méthode.

Elle contient :

- projet scientifique ;
- publications ;
- bibliographie ;
- méthodes ;
- corpus ;
- limites ;
- débats ;
- gouvernance ;
- versions ;
- droits ;
- crédits ;
- financement.

## 4. Architecture éditoriale des activités

Chaque activité doit proposer plusieurs niveaux d'accès.

### Niveau 1 - Présentation rapide

La page centrale de l'activité présente :

- question directrice ;
- âge ;
- durée ;
- objectifs ;
- matériel ;
- contextes classe et musée ;
- documents disponibles ;
- statut de publication.

### Niveau 2 - Ressources prêtes à utiliser

Ce niveau contient :

- fiche élève ;
- matériel imprimable ;
- cartes ;
- grille ;
- support d'observation ;
- exemple de production, lorsque pertinent.

### Niveau 3 - Documentation professionnelle

Ce niveau contient :

- guide enseignant ;
- guide musée ;
- objectifs ;
- procédure ;
- analyse a priori ;
- obstacles ;
- relances ;
- différenciation ;
- évaluation ;
- correction raisonnée ;
- liens PER.

### Niveau 4 - Approfondissement

Ce niveau contient :

- sources ;
- bibliographie ;
- contexte scientifique ;
- limites ;
- débats ;
- historique des interprétations ;
- ressources externes.

Un utilisateur ne doit pas être obligé de lire le niveau 4 pour imprimer et comprendre une fiche élève.

## 5. Principes pédagogiques

Les activités s'adressent principalement aux élèves de 8 à 12 ans.

Elles doivent être :

- accessibles ;
- exigeantes ;
- non infantilisantes ;
- fondées sur l'observation ;
- structurées ;
- ouvertes à l'argumentation ;
- compatibles avec des niveaux différents.

La progression privilégiée est :

1. observer ;
2. décrire ;
3. formuler une hypothèse ;
4. comparer ;
5. rechercher des indices ;
6. vérifier ;
7. réviser ;
8. conclure avec prudence ;
9. communiquer.

Les activités ne doivent pas se réduire à :

- mémoriser un mot ;
- recopier une réponse ;
- reconnaître une couleur ;
- associer deux cartes grâce à un code graphique ;
- deviner sans argumenter.

Chaque tâche doit préciser la production attendue.

## 6. Plan d'études romand

Les correspondances avec le PER doivent être construites à partir des manuels complets disponibles dans `_private-inputs/per/`.

Les domaines principalement concernés sont :

- Mathématiques et Sciences de la nature ;
- Sciences humaines et sociales ;
- Français ;
- Arts visuels ;
- Formation générale et éducation numérique, lorsque pertinent.

Chaque correspondance doit distinguer :

- objectif principal ;
- objectif mobilisé ;
- ouverture interdisciplinaire.

Ne pas affirmer qu'une activité couvre entièrement un objectif du PER.

Employer des formulations comme :

> Cette activité contribue notamment au développement de...

> Cette activité mobilise certains éléments de...

> Cette proposition peut s'intégrer dans une séquence travaillant...

Les codes et formulations exacts doivent être vérifiés dans les manuels privés avant publication.

## 7. Rigueur scientifique

Le projet distingue toujours :

- observation ;
- description ;
- hypothèse ;
- interprétation ;
- vérification ;
- conclusion ;
- incertitude.

Une formulation doit indiquer clairement son degré de solidité.

### Formulations recommandées

- "Le document montre..."
- "Cet indice permet de proposer..."
- "L'interprétation la plus probable dans ce dossier est..."
- "Cette fonction est attestée dans..."
- "Cette hypothèse reste discutée..."
- "Les informations disponibles ne permettent pas de conclure..."

### Formulations à éviter

- "Les Anciens faisaient toujours..."
- "Cet objet est forcément..."
- "Tous les astragales servaient à..."
- "Les astragales sont les premiers dés."
- "Cette image prouve tout le récit."
- "Cette perforation montre qu'il s'agit d'une amulette."

Les cultures, périodes et régions ne doivent pas être fusionnées.

## 8. Terminologie

Les termes suivants ne sont pas interchangeables :

- astragale ;
- talus ;
- osselet ;
- talon ;
- cheville ;
- tarse ;
- jarret ;
- calcanéus ;
- jeu ;
- dé ;
- tirage au sort ;
- divination ;
- amulette ;
- offrande.

Les documents élèves peuvent employer une terminologie simplifiée, mais elle ne doit pas devenir incorrecte.

Les guides adultes doivent expliciter les distinctions nécessaires.

## 9. Sources et bibliographie

Les sources prioritaires sont :

1. publications scientifiques ;
2. éditions universitaires ;
3. bases de collections muséales ;
4. ressources institutionnelles ;
5. documents officiels du PER ;
6. ressources pédagogiques reconnues.

Les pages généralistes et blogs ne doivent pas constituer la seule source d'une affirmation importante.

Toute affirmation précise concernant une culture, une période, un objet, une pratique, une traduction, une espèce ou une fonction doit pouvoir être reliée à une source identifiable.

Les citations longues sont évitées. Les contenus sont reformulés.

## 10. Statut des images

Chaque image publique doit être classée dans l'une des catégories suivantes :

- photographie scientifique ;
- photographie d'objet de musée ;
- source historique ou antique ;
- schéma scientifique ;
- illustration pédagogique ;
- reconstitution ;
- illustration contemporaine ;
- image générée par intelligence artificielle.

Ces catégories doivent rester explicites.

Une illustration pédagogique ne doit pas être présentée comme une source.

Une image moderne ne doit pas être présentée comme antique.

Une image générée ne doit jamais être présentée comme preuve historique, archéologique ou anatomique.

## 11. Intelligence artificielle et génération d'images

L'utilisation de `imagegen` est autorisée pour :

- couvertures ;
- éléments décoratifs ;
- scènes contemporaines ;
- illustrations narratives ;
- ambiances ;
- pictogrammes ;
- prolongements créatifs ;
- images explicitement présentées comme interprétations modernes.

Elle est interdite pour produire :

- un schéma anatomique scientifique ;
- une photographie d'ossement prétendument réelle ;
- un objet archéologique fictif présenté comme authentique ;
- un faux vase grec ;
- une fausse source historique ;
- une restitution scientifique non signalée ;
- une correction anatomique de référence.

Toute image générée doit être accompagnée de la mention :

> Illustration contemporaine générée avec une intelligence artificielle. Elle ne constitue pas une source historique ou scientifique.

Le prompt, la date, l'outil et les principales modifications doivent être conservés dans les métadonnées internes.

## 12. Placeholders

Lorsqu'une ressource validée manque :

- conserver un placeholder ;
- indiquer clairement ce qui manque ;
- enregistrer le besoin dans le registre des ressources manquantes ;
- ne pas utiliser une image décorative trompeuse ;
- ne pas attribuer à la ressource le statut "prêt à utiliser".

Un placeholder doit préciser :

- type de ressource attendu ;
- sujet ;
- orientation ;
- échelle éventuelle ;
- source souhaitée ;
- validation nécessaire ;
- dossier cible.

Les placeholders peuvent être visibles dans les prototypes internes.

Sur le site public, une activité incomplète doit être identifiée comme prototype ou en cours de validation.

## 13. Modèles 3D

Les modèles 3D doivent être :

- scientifiquement identifiés ;
- associés à une espèce ou un objet précis ;
- accompagnés d'une licence ;
- documentés ;
- orientés ;
- décrits textuellement ;
- utilisables sans empêcher l'accès au contenu principal.

Pour chaque modèle, conserver :

- origine ;
- institution ;
- méthode de numérisation ;
- espèce ;
- côté anatomique ;
- échelle ;
- modifications numériques ;
- licence ;
- date de validation.

Le modèle 3D est un complément. Une activité doit rester réalisable sans WebGL ou sans tablette.

## 14. Impression

Le HTML constitue la source principale des documents.

Les PDF sont des exports ou instantanés de publication, pas la source éditoriale principale.

Toute ressource annoncée comme imprimable doit être testée :

- au format A4 ;
- en couleur ;
- en niveaux de gris ;
- avec une imprimante scolaire standard ;
- avec des marges réalistes.

Les documents imprimés doivent rester compréhensibles hors du site.

Ils doivent indiquer au minimum :

- titre ;
- activité ;
- public ;
- version ;
- date ;
- sources ou renvoi vers les sources ;
- crédits des images ;
- statut.

## 15. Accessibilité

Le site suit autant que possible les principes WCAG 2.2.

Les exigences minimales sont :

- navigation clavier ;
- focus visible ;
- titres structurés ;
- h1 unique ;
- textes alternatifs ;
- descriptions longues ;
- contraste ;
- zoom à 200 % ;
- tableaux accessibles ;
- information non dépendante de la couleur ;
- réduction du mouvement ;
- mise en page responsive ;
- contenu principal utilisable sans JavaScript lorsque possible.

L'accessibilité n'est pas considérée comme validée uniquement par un test automatisé.

## 16. Ton rédactionnel

Le ton du projet est :

- clair ;
- sérieux ;
- accueillant ;
- précis ;
- non infantilisant ;
- prudent ;
- pédagogique.

Les textes élèves utilisent des phrases courtes, mais pas un vocabulaire artificiellement enfantin.

Les textes adultes peuvent être plus techniques, à condition de définir les termes nécessaires.

Le projet évite :

- le ton sensationnaliste ;
- les certitudes excessives ;
- les anecdotes non sourcées ;
- les récompenses artificielles ;
- les personnages décoratifs inutiles ;
- les formulations vagues du type "objet mystérieux" sans explication.

## 17. Multilinguisme

La priorité éditoriale est de stabiliser entièrement la version française.

Une langue ne doit être annoncée comme disponible que si le parcours principal et les ressources essentielles sont réellement traduits.

Les traductions doivent être réalisées ou relues par une personne compétente.

Une interface partiellement traduite ne doit pas laisser croire que toutes les ressources existent dans cette langue.

Cette décision pourra être révisée lorsque les dossiers français seront stabilisés.

## 18. Statuts de publication

Les statuts sont distincts.

### Prototype

La structure existe, mais le contenu, les médias ou les validations sont incomplets.

### Contenu en cours

Le contenu est rédigé, mais la validation scientifique ou pédagogique n'est pas terminée.

### Validation scientifique effectuée

Les affirmations et supports scientifiques ont été relus par la personne compétente.

### Droits confirmés

Les droits et obligations d'attribution des médias sont documentés.

### Prêt à imprimer

La ressource a été testée en A4 et en niveaux de gris.

### Prêt à utiliser

Le contenu, les médias, les droits, les instructions et l'impression ont été validés.

Un document ne doit pas être déclaré "prêt à utiliser" uniquement parce que sa page HTML fonctionne.

## 19. Versions et corrections

Chaque ressource publique doit avoir :

- un numéro ou identifiant de version ;
- une date de révision ;
- un statut ;
- une liste des principales modifications lorsque nécessaire.

Les corrections scientifiques importantes doivent être documentées.

Le site doit permettre de signaler :

- une erreur ;
- un lien cassé ;
- une difficulté d'utilisation ;
- une question relative aux droits.

## 20. Gouvernance humaine

Codex peut :

- structurer ;
- intégrer ;
- vérifier les liens ;
- contrôler l'affichage ;
- analyser les manuels fournis ;
- générer des gabarits ;
- produire des inventaires ;
- appliquer les décisions éditoriales ;
- signaler les incohérences.

Codex ne peut pas déclarer seul :

- une interprétation archéologique comme validée ;
- une identification d'espèce comme certaine ;
- une image comme juridiquement réutilisable sans preuve ;
- un schéma anatomique comme scientifiquement correct ;
- une activité comme pédagogiquement validée en classe ;
- une correspondance PER comme définitive ;
- un objet comme ayant eu une fonction précise.

Ces validations restent humaines.

## 21. Décisions encore ouvertes

Les décisions suivantes doivent rester explicitement marquées "à décider" tant qu'elles ne sont pas confirmées :

- licence du code ;
- licence des textes pédagogiques ;
- statut des traductions ;
- composition de l'équipe de validation ;
- politique de versionnement ;
- méthode de génération et d'archivage des PDF ;
- modèles 3D retenus ;
- espèces retenues pour l'activité 2 ;
- corpus historique final de l'activité 3 ;
- objets archéologiques finaux de l'activité 4 ;
- formulaire ou adresse de signalement ;
- niveau de publication des dossiers encore incomplets.
